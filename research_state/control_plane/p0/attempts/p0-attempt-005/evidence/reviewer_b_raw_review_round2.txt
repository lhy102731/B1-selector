BLOCKER: nonce_secret_handling: plaintext nonce and root capability exist in process memory during activation and could leak via core dumps or /proc/<pid>/mem if the parent process is compromised, and the HMAC domain separation relies solely on a string constant that is not versioned in the DB, allowing a future domain-separation constant change to silently invalidate all stored fingerprints without detection.
BLOCKER: final_eval_cas: the saga_state CHECK constraint allows AUTHORIZED -> CLOSED direct transition (skipping CONSUMED/EVALUATING/RESULT_STAGED) because the CHECK only validates the state value, not the transition path, and the versioned CAS is only enforced in application code, not in the DB trigger, so a compromised or buggy writer can skip saga phases.
BLOCKER: final_eval_result_binding: the result_claim_ref UNIQUE constraint is on the column value alone, but the create-once fixed claim is generated from the ticket_id and a counter, so two different tickets with the same counter value could produce identical claim references, allowing a result claim to be bound to two tickets if the counter resets or is not globally unique.
BLOCKER: operational_integrity: derived tables are created without any FK constraints to the sealed access event chain, so a direct SQL UPDATE on a derived table row (e.g., ops_campaign_projection.campaign_id) will not trigger any integrity violation, and the verify_access_integrity recompute only detects missing anchors, not authorized-looking modifications to derived data.
BLOCKER: migration_rollback: the v3->v4 migration records the canonical chain root in operational_meta but does not store the previous v3 schema version or a rollback manifest, so if the migration fails after WAL switch but before BEGIN IMMEDIATE, the store is left with WAL journal_mode and v3 schema, and the rollback to v3 requires a manual WAL-to-rollback-journal switch that is not automated or tested.
MUST_FIX: coordinator_lease: the FinalEvalRecoveryLease is exchanged from an independent maintenance TaskExecutionLease, but the lease ID is not bound to the process PID or a unique token, so a stale lease from a previous process (after a hard crash) could be re-acquired by a new process if the old lease expires exactly at the same time as the new one starts, causing two processes to think they hold the exclusive lease.
MUST_FIX: coordinator_replay: the envelope manifest is read as a committed regular blob from the envelope commit, but the diff SHA-256 is computed over the blob bytes without binding the envelope commit OID into the diff hash, so an attacker who can create a new commit with the same blob bytes and a different parent chain could replay the envelope with a tampered commit history.
MUST_FIX: git_evidence_path: the git_evidence reader locks commit+mode+OID+bytes+SHA-256 but does not lock the tree path as a canonical absolute path within the repository, so two different paths (e.g., `foo/../bar` and `bar`) that resolve to the same blob could be confused, allowing a symlink-free but path-aliased read to bypass the no-traversal check.
MUST_FIX: sql_injection: the schema-probing specs in migration mode are built by concatenating user-provided table names from the v1 authority store into SQL queries without parameterization (e.g., `SELECT count(*) FROM " + table_name + "`), and while the input is validated to be alphanumeric, a table name with a quote character would break out (tested with `'; DROP TABLE tasks;--` which was not rejected).
MUST_FIX: final_eval_holdout: the UNIQUE constraint on (research_plan_sha256, holdout_id) and (research_plan_sha256, holdout_sha256) allows a ticket to be created with a holdout_id that references a different research_plan_sha256 than the ticket's own plan, so a malicious or buggy client could bind a ticket to a holdout from a different research plan, causing the final eval to evaluate against the wrong holdout.
MUST_FIX: derived_tables_auth: while derived tables have no ticket/secret/lease/grant columns, they do have a `campaign_id` column that is not FK-constrained to the campaigns table, and a direct UPDATE on ops_campaign_projection.campaign_id could change which campaign a projection belongs to, potentially causing an execution path to read from the wrong campaign's projection.
MUST_FIX: wal_policy: the require_wal flag is set per-connection but the check `journal_mode=WAL` is only verified before `BEGIN` and not after a `ROLLBACK` or `COMMIT`, so if the journal mode is changed by another connection during a transaction (e.g., via `PRAGMA journal_mode=DELETE` which locks the DB), the current connection could continue to write without WAL protection.
SHOULD_FIX: coordinator_downgrade: the v1 bootstrap mode is rejected on v2 authority stores via user_version check, but the v2->v1 downgrade path after a successful migration is not blocked, and if the operator manually sets user_version=1 on a v2 store with new v2 event rows, the system will treat it as a v1 store and may apply v1-only operations to v2 data.
SHOULD_FIX: backup_verification: the SQLite-backup-API snapshots have hashed manifests, but the hash is computed over the manifest bytes only, not over the actual backup file content, so a corrupt backup file that is not reflected in the manifest would pass verification; the hash should cover the backup file itself.
SHOULD_FIX: git_command_injection: the activation coordinator uses fixed argv vectors for git commands, but it does not use `--` to separate options from paths, so a repository path that starts with `-` (e.g., `-c` or `--work-tree`) could be interpreted as a git option, causing unintended behavior.
SHOULD_FIX: crash_matrix_realism: the crash matrix uses real subprocess hard exits, but it does not test a crash during the WAL switch in migration mode (the window between the WAL switch verification and the BEGIN IMMEDIATE), which is the most likely point of corruption.
SHOULD_FIX: outbox_idempotency: the post-FINISH idempotent outbox mirror/ack uses a `message_id` as the dedup key, but the `message_id` is derived from the ticket_id and the event type, so a replayed envelope with the same ticket_id but a tampered blob (if the blob hash is not verified at outbox write time) would be silently deduplicated and not raise an alert.
SHOULD_FIX: toctou_activation: the activation coordinator reads the envelope manifest as a committed blob and checks HEAD equals manifest base, but there is a TOCTOU window between the HEAD check and the git read where another process could advance HEAD, making the subsequent reads inconsistent with the verified state.
SHOULD_FIX: secret_in_logs: while the bearer secret is zero occurrences in fixture tree, DB bytes, child argv/env and logs, the activation coordinator logs the envelope commit OID and the manifest path, and if the manifest path contains a secret-like substring (e.g., `/tmp/secret-`), it could leak a hint to the log reader.
OK: nonce_fingerprint_scope: the nonce fingerprint uses HMAC-SHA256 with domain separation and the plaintext nonce is never written to DB/outbox/log, and the raw bytes are tested to ensure zero occurrences; this is sound as long as the domain separation constant is not changed.
OK: final_eval_cas_transaction: the begin is in one writer transaction and the CAS advance rejects skip/backward/wrong-version in application code, and the column-level UNIQUE constraints are enforced by SQLite; this is sound except for the direct transition path bypass noted above.
OK: operational_access_chain: the access_event_integrity chain is built in the same transaction as the access append, and verify_access_integrity fails closed on any mismatch; this is sound for the sealed event chain but does not protect derived tables.
OK: migration_event_preservation: the migration never rewrites original event rows and only adds derived tables + integrity chain in a new transaction, and any anchor failure rolls back; this is sound for event preservation.
OK: coordinator_single_process: the single parent process holds one JIT ticket/lease in memory, and phases are strictly forward; this is sound except for the lease ID not being bound to a unique token.
OK: crash_matrix_pre_begin: the pre-BEGIN crash test verifies zero Authority/branch change, and the crash matrix uses real subprocess hard exits; this is sound for the tested windows.
OK: git_blob_reading: the git_evidence reader reads committed regular blobs only and rejects symlink/tree/traversal/NUL, and uses fixed argv vectors without shell; this is sound except for the path alias and missing `--` separator.
OK: derived_tables_no_auth: derived tables have no ticket/secret/lease/grant columns, so they cannot authorize execution; this is sound by design.
OK: httpx_pin: httpx==0.25.2 is pinned and ag2 is installed with --no-deps, and 1593 control-plane tests pass; this is a documented deviation that is empirically verified.
VERDICT: FAIL
Rationale: Multiple BLOCKER findings on saga state transition enforcement, result claim uniqueness, derived table integrity, and migration rollback leave the corrective recovery vulnerable to state machine bypass, cross-ticket binding, and silent derived data corruption, despite strong evidence on nonce handling and access chain integrity.

# B1 V3 完整实现计划

> 2026-05-30 | 基于 V1(波生命周期) + V2(多因子评分) 融合方案

---

## 一、背景

### 1.1 当前系统

| | V1 (原始B1) | V2 (指纹优化器) |
|------|------|------|
| 文件 | `strategy/unified_b1_strategy.py` + `pattern_matcher.py` | `_fp_optimizer.py` |
| 信号生成 | 波生命周期检测 + 形态匹配 | 宽松预过滤提取 |
| 质量评估 | 24案例6维相似度 (0-100%) | 60+因子加权评分 (0-100) |
| 过滤方式 | 硬过滤链，不合格直接丢弃 | 阈值过滤 + 可选门 + 评分排名 |
| 退出规则 | 无（纯选股） | 完整退出引擎（止损/T+3/止盈） |
| 参数优化 | 无 | 网格搜索 |
| 优点 | 波群合并/断裂检测/洗盘逻辑 | 多因子评分/退出引擎/扫参 |
| 缺点 | 模块内部全部硬编码，未经回测验证 | 波逻辑弱（简化版surge_quality），无形态匹配 |

### 1.2 核心问题

1. V1的模块（波质量/波断裂/洗盘）**本身可能也不好**，不能当黑盒直接参数化
2. V2缺失V1的波生命周期分析（异动群识别/群合并/波断裂）
3. 两套系统各有所长但无法协同

### 1.3 目标

新建独立系统，综合两者最佳部分。**没有任何硬编码数字，每个条件、每个阈值都独立可回测**。不预设V1或V2的正确性——默认值从V1/V2抄过来作为起点，但每个值都可以被质疑和扫参替换。

## 三、条件分类

### 3.1 分类标准

并非所有条件都应该成为评分因子。必须区分硬过滤和评分因子：

| 类型 | 判断标准 | 处理方式 | 例子 |
|------|---------|---------|------|
| **A. 结构硬过滤** | 定义B1是什么，不满足=不是B1 | 逻辑不可关，阈值可扫参 | White>Yellow, DIF>0 |
| **B. 阈值过滤** | 连续值超界=硬排除，界内=评分因子 | 阈值扫参，界内值流入D类因子 | J>30排除，界内q_J评分 |
| **C. 可选硬过滤** | 二进制门，可独立开关 | 默认对齐V1，每个独立回测 | 要求阳线，要求无派发 |
| **D. 评分因子** | 连续"有多好"，弱项可被补偿 | 全部独立开关+可调权重 | 缩量程度，波健康度 |
| **E. 结构通道** | 替代进入路径，不是过滤不是因子 | 逻辑分支 | 洗盘通道，超级B1 |
| **F. 退出规则** | 持仓管理，独立维度 | 全部可开关 | 止损，T+3，止盈 |

### 3.2 分类理由（逐条件论证）

**为什么 White>Yellow、DIF>0、60日未翻倍、市值下限 归入A类（结构硬过滤）？**

因为这些是B1的定义性条件。白线在黄线之下=下降趋势，做B1（均值回归回踩）没有意义。DIF<0=MACD空头区间，做反弹是逆势。翻倍股已透支。仙股流动性不足。这些没有"程度"可言，不满足就不是B1。

**为什么J值、量比、换手率归入B类（阈值+评分）？**

以J值为例：J>30说明已脱离超卖区→硬排除。但在J<30的范围内，J=5比J=25更好（更超卖）→可以用q_J给分。同理，量比>1.5=放量回踩→排除。界内量比0.3比1.3更好→q_vol_sh给分。

**为什么波质量归入C类（可选硬过滤）而非A类（结构）？**

因为"多健康的波才算合格"本身就是一个需要回测验证的问题。也许涨幅30%的波比涨幅60%的波更好（更温和），也许红绿比1.0就够了不需要1.2。这些阈值需要扫参，所以整个模块是可开关的C类。

**为什么形态匹配降级为D类（评分因子）而非主评分？**

V1用24案例相似度做主排序。但24个案例是否代表市场全部？也许有些好股票形态不相似但其他维度优秀。改为D类因子后：如果形态相似确实重要，q_pattern_sim权重高自然起作用；如果不重要，回测会证明权重应降低。

### 3.3 "门+分"模式

C类中很多条件在D类也有对应的评分因子。这不是重复，而是两层独立控制：

- **门（C类）**：不满足=直接丢弃，二进制
- **分（D类）**：连续度量有多好，加权计入总分

举例：`require_green=True`（C类门）=当日必须收阳。`q_green=1`（D类分）=当日收阳给1分×权重。可以：
- 只开门：阳线是硬要求，但不在评分中加权
- 只评分：不强制阳线，但阳线能加分
- 两者都开：阳线是硬要求，且阳线额外加分
- 两者都关：不考虑阳线

### 3.4 已解决的冲突

设计过程中发现的冲突及解决方案：

| 冲突 | 说明 | 解决方案 |
|------|------|---------|
| V1碗区 vs V2 vs_white范围 | 两套不同的位置定义 | 统一用V1碗区(A5)，V2的vs_white范围作为可选收紧条件(C类) |
| V1量比 vs V2量比 | V1用vol/20d波内峰值，V2用vol/5d均量 | 两套并存：B2(V1方式) + B3(V2方式)，独立参数 |
| 波质量数据源 | V1复杂波分析 vs V2简化surge_quality | 统一用V1输出，q_surge/q_retrace从V1波分析计算 |
| cs_shadow_max归错类 | 连续百分位阈值却被放在二进制C类 | 移到B类（阈值过滤） |
| white_yellow_gap未计算 | `_fp_optimizer.py:668`用了s.get('white_yellow_gap',0)但从未设置 | 修复：在信号提取中补上计算 |
| q_pe/q_pb数据依赖 | PE缓存在时能算，不在时恒为0 | 无数据时跳过该因子（不参与加权） |

## 五、系统架构

### 5.1 四层流水线

```
Layer 0: 信号提取 (Signal Extraction)
  A1-A4: 结构硬过滤（快速否决）
    ↓
  V1波分析: analyze_wave() → 输出波特征字典
    ↓
  A5: 碗区位置检查（或洗盘通道）
    ↓
  B1-B9: 阈值过滤（超界=排除，界内=特征值保留）
    ↓
  C1-C17: 可选硬过滤（开启的必须全部通过）
    ↓
  E: 通道判定（洗盘/超级B1标记）
    ↓
  输出: 候选信号 [{code, date, 全部特征向量}]

Layer 1: 质量评分 (Quality Scoring)
  候选特征 → 计算所有D类因子 → 加权求和 → quality_score (0-100)

Layer 2: 过滤排名 (Filter & Rank)
  quality_score_min + top_n_per_day → 每日精选信号

Layer 3: 回测模拟 (Simulation)
  日线数据 + 精选信号 → F类退出规则 + 仓位管理 → equity + trades + metrics
```

### 5.2 数据流

```
indicators_cache/*.parquet  ──→  extract_signals()  ──→  raw signals
    (已有预计算指标)                  (Layer 0)              (特征向量)

raw signals  ──→  score_candidates()  ──→  ranked signals
                  (Layer 1-2)               (quality_score排序)

ranked signals  ──→  simulate()  ──→  equity_df + trades_df
                     (Layer 3)          (回测结果)
```

### 5.3 文件结构

```
新增文件：
├── docs/b1_v3_factor_list.md          ← 已创建，86因子完整清单
```

## 六、退出规则

继承V2退出引擎，全部独立开关：

| # | 规则 | 参数 | 默认 | 说明 |
|---|------|------|------|------|

## 八、扫参方法

三阶段混合策略（避免纯单独和纯累积的各自缺陷）：

| 阶段 | 方法 | 目的 |
|------|------|------|
| **Phase A: 单独筛选** | 每个OFF因子单独开启 vs 基线，跑跨期回测 | 快速排除噪音，标记正/负/无效 |
| **Phase B: 累积构建** | 有效因子按优先级叠加，改善→保留，退化→丢弃 | 处理交互效应，构建有效参数组合 |
| **Phase C: 消融验证** | 从最终组合逐个关闭→回测 | 确认每个保留因子仍有正向贡献 |

跨期验证：2016-2020 和 2021-2026 两段独立测试。两段都有效才算通过。

## 十、关键设计原则

1. **没有任何硬编码数字** — 所有阈值、权重、开关都是参数，默认值从V1/V2抄来
2. **波生命周期统一用V1版本** — 异动群识别+合并+断裂检测，V2简化版不使用
3. **门+分模式** — 同一条件可同时做硬过滤(C类)和评分因子(D类)，独立控制
4. **不修改现有V1/V2文件** — 新系统完全独立
5. **默认值对齐V1** — 初始行为与V1一致，方便验证正确性，然后逐步偏离扫参
6. **一切可回测** — 任何参数修改后只需删除信号缓存重新跑

## Problem

The current Git source identity captures the complete `HEAD` commit and tree in
the code-freeze manifest. The official Gate and its receipts are created after
that freeze and must then be committed as exact Git evidence. That evidence-only
commit necessarily changes both `HEAD` and the full tree, so
`verify_current_git_inventory()` immediately rejects the Gate it just closed.

Repeating the refresh cannot converge: every refresh produces another Gate
evidence commit and therefore another source identity. This is a source-identity
self-reference, not AuthorityStore corruption. No Authority mutation is allowed
under this request until the public behavior below is implemented and reviewed.

## Requested bounded behavior

Keep the existing frozen commit/tree as the authoritative executable-source
identity. Permit a later verifier to accept a descendant `HEAD` only when every
commit after the frozen commit is an immutable evidence-only commit satisfying
all of these conditions:

1. the frozen commit is an ancestor of the current `HEAD`;
2. every post-freeze commit is single-parent (no merge ambiguity);
3. every changed path in every post-freeze commit has status `A` only;
4. every added path is a regular, non-reparse `.json` file below the exact
   `research_state/control_plane/` namespace;
5. no source, test, configuration, policy source, executable, dependency,
   scheduler artifact, existing audit record, or previously added evidence file
   is modified, deleted, renamed, copied, or mode-changed;
6. the current bounded entry inventory and runtime dependencies still equal the
   frozen inventory;
7. active tracked dirt, unsafe index flags, untracked executable drift, and
   runtime dependency drift continue to fail closed.

The exception is only a verified descendant evidence suffix. It does not allow
ordinary source maintenance after a freeze and does not reinterpret an old Gate
as covering new executable bytes.

## Public-interface TDD slices

Implement one behavior at a time through `build_code_freeze_manifest()` and
`verify_current_git_inventory()`:

1. RED then GREEN: a clean freeze remains valid after one committed, newly
   added control-plane JSON evidence file;
2. RED then GREEN: multiple single-parent additions in the same namespace
   remain valid;
3. RED then GREEN: a committed source, test, configuration, executable, or
   runtime change is rejected;
4. RED then GREEN: modification, deletion, rename, copy, type/mode change, or
   overwrite of any evidence path is rejected, including add-then-modify in the
   post-freeze suffix;
5. RED then GREEN: a merge commit or non-descendant history is rejected;
6. retain existing negative tests for dirty tracked source, unsafe index state,
   untracked executables, inventory drift, runtime drift, and Gate artifact hash
   mismatch;
7. prove an official Gate can be verified through public
   `PhaseGateVerifier.verify_bytes()` both immediately before and after its
   exact evidence-only Git commit.

## Post-approval security finding and resolution

The required independent security review found that the existing bare `git`
invocation allowed ambient `PATH` or a repository-local executable to run before
source identity verification. Closing the approved descendant-evidence behavior
without closing that execution path would leave the Gate forgeable.

The repair therefore pins the deployment Git runtime closure in the P0 TCB to:

- path: `D:/Git/mingw64/bin/git.exe`;
- launcher SHA-256: `cab4c4eea1d869cf9f7be73868dc9a90ad2df1b1b673e5f8c8714a576c25ea96`;
- closure: the launcher plus all 84 direct `*.dll` files in the same directory;
- closure SHA-256: `02466679eb920bca7fc64ec6113bd93833716039b1b9770f20c32e9fa0adaf93`.

Every invocation uses that absolute path with a minimal environment, rejects a
repository-contained or reparse-resolved runtime, and checks the locked bytes
and the complete runtime file set/identities before and after execution. Only the
required built-in commands are admitted, and `GIT_EXEC_PATH` plus `PATH` are
bound to the trusted directory. Git runs from that directory and receives the
repository only through an explicit `-C` argument, so repository files are not a
process/DLL search directory. Ambient and pre-import `PATH` poisoning, a
repository-local `git.exe`, DLL mutation/addition, and reparse aliases are covered
by public freeze regressions. A Git install or upgrade that changes this binding
fails closed and requires another explicit P0 TCB change request; runtime
discovery or silent fallback is forbidden.

Exact evidence-copy rejection is content-addressed: the verifier records every
frozen control-plane blob and accepted evidence blob OID and rejects any later
addition that reuses one. This intentionally enforces the approved prohibition
on copying an existing audit record even when its legacy extension is not JSON.
Git similarity detection remains enabled with an unlimited rename/copy limit only
as defense in depth; Gate safety no longer depends on that heuristic. Every new
blob is also size-bounded, strict-parsed through pinned Git `cat-file`, and must
equal its canonical JSON bytes exactly; an arbitrary file renamed to `.json` is
not evidence.

The V3.4.2 threat model does not claim to resist arbitrary concurrent code
execution under the same Windows principal that owns the CurrentUser DPAPI root
capability. Such a principal can decrypt the Authority root directly and already
controls the entire trust root. ABA replacement of the locked Git installation
or its signed DLL closure by that same principal is therefore outside this
control plane's security boundary; repository content, ambient environment, and
untrusted task code remain inside the boundary and must not select the runtime.

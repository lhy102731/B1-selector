# V3.4.1 Research Control Plane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use Superpowers `subagent-driven-development` for implementation and `test-driven-development` for every new behavior. Each step is tracked with a checkbox and must pass the two-stage review before the next task.

**Goal:** Add an auditable control plane around the existing Python research automation so every run has a frozen protocol, pinned data generation, access/taint lineage, independently checked evidence, content-addressed Learning Commit, safe cross-round memory, and mechanically gated campaign/holdout execution without changing production strategy logic.

**Architecture:** New control-plane modules live under `research_automation/control_plane/` and write only to `research_state/control_plane/` plus the existing safe output root. Existing runners remain compatibility inputs; they cannot be trusted writers. The controller is the only component allowed to advance phases, and the Ledger/Memory views are derived from append-only control-plane events rather than becoming a second source of truth.

**Tech Stack:** Python 3.13, standard library (`dataclasses`, `enum`, `hashlib`, `json`, `sqlite3`, `pathlib`, `tempfile`, `fcntl/msvcrt` as appropriate), existing PyYAML/pandas utilities, and the repository's `unittest` test style. No new third-party dependency is introduced in V3.4.1.

## Baseline and verified current seams

- `research_automation/kbase_ag2_full_cycle.py` creates an atomic manifest but accepts arbitrary stage/status strings and trusts Runner `status.json`/`promotion_gate_passed`.
- `research_automation/autonomous_runner.py:294-319` can write through `ag2_research.knowledge_bridge` when `KBASE_WRITEBACK` is unset because its default is `"1"`.
- `research_automation/discovery_execution_bridge.py:26-35` has no approved/executed protocol hashes or data-generation identity.
- `research_automation/experiment.py` is a legacy lifecycle object and must remain compatible; it is not the V3.4 Claim/Learning Packet contract.
- `ag2_research/orchestrator.py:86-143` has a text-overlap RegistryGate; the new LearningGate must not silently inherit its global hard-reject behavior.
- `utils/raw_parquet_cache.py` treats CSV as source of truth and uses mtime freshness; V3.4 wraps this behavior with generation identity rather than replacing the cache.
- `tools/update_today_em_client.py:64-138` already treats `no_today_bar` as legal and validates daily checkpoints; V3.4 preserves that behavior while making publication generation-safe.

## Dependency and parallelization plan

| Lane | Work | Depends on | Shared-file rule |
|---|---|---|---|
| A | P0/P1 contracts, entry guard, protocol compiler | baseline only | owns `contracts.py`, `entry_guard.py`, entrypoint adapters |
| B | P2 generation | contracts API frozen | owns `generation.py`, daily/cache adapters |
| C | P3/P4 access/evidence | contracts; generation identity types | owns `access.py`, `evidence_learning.py`, cycle adapter |
| D | P5/P6 memory/campaign | P4 commit/evidence gate | owns `memory.py`, `campaign.py`, runner adapter |
| E | P7/P8 operations/evaluator | campaign contracts frozen | owns `evaluator.py`, ops tests and final gate adapter |

Lane A must complete its contract gate before B/C begin. B and the contract-only part of C may proceed in parallel after that gate. D waits for C's Evidence/Commit gate. E waits for D's Campaign gate. No two lanes edit the same file concurrently.

## Global TDD and verification commands

Each RED/GREEN step uses the smallest targeted command:

```powershell
python -m unittest tests.test_control_plane_<component> -v
```

After a task's targeted tests pass:

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
```

If a task changes backtest/signal/parameter handling, run the AGENTS-required isolated known-good verification backtest with its exact user-approved parameters and an output/cache directory outside production paths. Do not run it for control-plane-only tasks.

## Explicitly not in scope for V3.4.1

- Strategy signal/parameter/model changes or production promotion.
- Rewriting the 84GB data set, changing CSV source-of-truth semantics, or deleting research artifacts.
- Multi-tenant storage, cold archive policy, UI/dashboard, configurable LLM summaries, or a bulk audit-export product.
- Replacing the existing AG2 research workflow or `Experiment` legacy object in one pass.
- Running a real multi-round Campaign or consuming Final Holdout during implementation.

## Stage gates

P0/P1 must prove entry closure and canonical identity before any data or evidence work. P2 must prove generation pin/mutation behavior before access events are trusted. P3/P4 must prove access/taint/evidence semantics before Learning Commit; a clean run with no material claim is recorded as NO_MATERIAL_FINDING and never becomes an empty packet. P5/P6 must prove scoped memory and dry-run campaign control before any authorized two-round control-plane test. P7/P8 remain implementation-only until a separate user authorization consumes a one-time Final Eval token.

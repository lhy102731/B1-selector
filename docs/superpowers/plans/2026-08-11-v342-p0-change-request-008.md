## 1. 目标

在不重写任何旧 receipt、Gate、closure 或数据库行的前提下，一次性修正三个 sealed-TCB 边界，使 P6/P7/P8/C0 corrective attempts 拥有可重复验证的 committed-Git 可信根：

1. **Committed Git evidence / activation**：Gate build/verify 只接受 committed regular blobs；单一 single-process activation coordinator；唯一一次按 blob hash 批准的 v1 source-bootstrap 例外。
2. **Authority v1→v2**：Final Eval 全局唯一性、recovery 能力、result claim，HMAC nonce fingerprint。
3. **Operational v3→v4**：WAL/NORMAL/busy timeout、四张 derived tables、`ops_access_event_integrity` sealed sidecar chain、受控 migration/backup/rollback。

## 2. Delta 1 — committed Git evidence contract 与 activation coordinator

- 新建 `research_automation/control_plane/git_evidence.py`：只接受仓库内规范化 ref 与锁定 commit，返回 commit、mode、OID、byte count、raw bytes、SHA-256；通过锁定 Git executable 读取，不 shell 拼接、不跟随 symlink、不允许 submodule/tree。
- 修改 `inventory.py`、`gates.py`、`cli.py`：`PhaseGateVerifier` 与 Gate build CLI 对 task report、baseline、freeze、inventory、policy、scheduler 全部使用 committed reader；`GateReport V1` 字段不扩张。
- 新建 `research_automation/control_plane/activation_coordinator.py`：单进程持有内存 capability，phase 固定 `VALIDATE→ISSUE→BEGIN→FAST_FORWARD→VERIFY→TEST→RECEIPTS→FINISH→OUTBOX`；bearer secret 不写入 child/argv/env/disk/log/evidence。
- v1 source-bootstrap 例外：从 locked Git object 读取、经 `ACTIVATE_CANDIDATE phase=P0 task=P0-SOURCE-BOOTSTRAP ... bootstrap_blob_sha256=<sha256>` 独立批准的 coordinator regular blob，由当前 v1 Authority 签发 ticket，仅允许 source fast-forward/pre-migration tests/v1 finish，在任何 live schema write 前 terminal。
- 测试面：`tests/test_control_plane_git_evidence.py`、`tests/test_control_plane_git_source_identity.py`、`tests/test_control_plane_gates.py`、`tests/test_control_plane_activation_coordinator.py`。

## 3. Delta 2 — Authority schema v1→v2（Final Eval uniqueness / recovery / result-claim）

- `stores.py` 保留 Authority v1/v2 的 expected schema identity；`sqlite_uow.py` 增加 store-specific durability policy。
- 新增 `final_eval_authorizations_v1` 表，固定字段：ticket ID、request SHA、authority plan hash、research plan SHA、campaign ID/SHA、holdout ID/SHA、nonce fingerprint、saga state/version、safe result object ref/hash、fixed result claim ref/hash、terminal binding、timestamps。**表不存 raw nonce、secret、holdout path、label、metrics 或 result bytes。**
- 全局唯一约束覆盖：nonce fingerprint、`(research_plan_sha256, holdout_id)`、`(research_plan_sha256, holdout_sha256)`、request hash、ticket、fixed result claim。
- 一次性冻结合法 transitions：`AUTHORIZED → CONSUMED → EVALUATING → RESULT_STAGED → CLOSED → AUTHORITY_TERMINAL`；每步 versioned CAS，禁止 skip/backward。
- 四个 sealed 能力：safe-state/binding read scan；result object+fixed claim CAS 为 `RESULT_STAGED`；由独立 maintenance TaskExecutionLease 换取的、无 `OPEN_HOLDOUT` 权限的 `FinalEvalRecoveryLease`；recovery CLOSED/Authority-terminal/outbox transition。recovery 不能构造 data handle、不能把 ticket 退回 `ISSUED`、不能重新评估。
- `access.py`：新 access append 与 sealed integrity sidecar 同 transaction 提交。
- 测试面：`tests/test_control_plane_stores.py`、`tests/test_control_plane_sqlite_uow.py`、`tests/test_control_plane_access.py`、`tests/test_control_plane_campaign_store.py`。

## 4. Delta 3 — Operational schema v3→v4（durability / derived tables / access integrity）

- `stores.py` 保留 Operational v1/v2/v3/v4 expected schema identity。
- 新增四张 derived tables：`ops_projection_checkpoint`、`ops_campaign_projection`、`ops_backfill_checkpoint`、`ops_retention_metadata`，以及 sealed `ops_access_event_integrity` sidecar chain 与必要索引。**projection 只能加速 read model，不能反向签发 ticket、启动 cycle 或批准 publication。**
- `_SqliteUnitOfWork` 在每个新 Operational connection、每个 `BEGIN` 前设置并验证 bounded busy timeout 与 connection-local `synchronous=NORMAL`，并验证 journal mode。
- v3→v4 迁移：quiescence/backup 后先在 transaction 外执行并验证 `PRAGMA journal_mode=WAL`；随后单个 `BEGIN IMMEDIATE` 增加 derived tables/index/metadata 与 `ops_access_event_integrity`，按 canonical access row 顺序建立历史 prefix chain 并记录 migration root，不重写原 access/campaign/journal rows，最后原子更新 user_version/schema identity。anchor 生成失败 rollback 全部 schema 变化。
- 新建 `store_migration.py`：只暴露 Authority/Operational 两个固定 target 的 quiescence、SQLite backup、staging rehearsal、validated publish 与 receipt；不接受任意 SQL/任意 target/自动 process termination。

## 6. Migration SQL semantics 与 stop rules

- 迁移 = 两段式（Authority v1→v2；Operational v3→v4），quiescent 窗口内执行；除 `P0-SOURCE-BOOTSTRAP`（必须先在 v1 terminal）与 `P0-STORE-MIGRATION`（v1 begin→migrate→v2 finish，同一父进程）两张 ticket 外，不得有其它 active ticket/cycle/lease。
- 若 migration 发现活跃 lease、运行中 cycle、打开数据库句柄或用户运行中的长任务，**必须停止并等待自然结束或用户指示**；不 terminate/reap/改参数。
- Windows 打开句柄导致失败时保留原 store，等待用户。
- 失败语义：发布前失败 → 原 store 不动；发布后无新事件 → 新授权下恢复已验证 backup；v2/v4 写入新事件后 → 禁止自动 downgrade，只能 forward-fix，除非用户明确接受丢弃新事件窗口。

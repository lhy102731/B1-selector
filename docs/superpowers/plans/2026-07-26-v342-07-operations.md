# V3.4.2 P7: Operations, Recovery, Audit, and Retention

## Objective

Prove that long-running control-plane operation does not progressively slow down, lose or double-count events, leak protected data, or grow without observable bounds.

OperationalJournal uses WAL, explicit busy timeout, one short writer transaction, and bounded batching for high-frequency access/usage. AuthorityStore remains low-frequency and fail-closed.

Projections update from `last_sequence` in O(new events). Full rebuild is an offline recovery operation with progress, integrity checks, and thresholds. Use the SQLite backup API for consistent operational backups. Authority corruption never triggers automatic recreation or clearing.

`run_research.py status|audit|doctor|export` is read-only. It shows campaign/cycle, budget, lease, roster, generation, evidence grade, access, usage status, pending publication, and failure causes without constructing a Runner, opening Holdout, or starting work.

Audit export is deterministic manifest plus hashes/references and excludes secrets, raw labels, Final Holdout, and unrelated large files.

Historical backfill is implemented only as a rate-limited, sharded, low-priority, pausable adapter. P7 does not run bulk backfill. Learning Packet metadata includes retention class, last referenced time, and archive eligibility. Only preview/staging data receives explicit TTL cleanup; scientific packets are not deleted by age.

Conflict and blocked states expose human-readable explanations and direct evidence references.

## Performance gate

Record machine, disk, Python, and SQLite versions for reproducible synthetic tests. Gate event append p95, incremental status/projection at 100k events, 10k-packet context construction, backup/restore, disk-full and low-disk boundaries, false lease reaping, audit redaction, backfill throttle/pause, retention safety, and CLI cold import.

Steady-state control-plane overhead targets at most 5% of cycle wall time. A breach fails the gate or requires a change request; it never silently weakens validation or roster.

# V3.4.2 P0R2: Trusted Entry and Authority Root

## Objective

Replace the stale P0R1 execution basis with a physically isolated authority root, operational journal foundation, one task-report contract, one reusable gate engine, and complete fail-before-effect entry closure. Adopt useful P0R1 code only after hash verification and revalidation.

## P0R2-0: Freeze the revised plan

Deliverables:

- approved `P0-CR-002`;
- ordered plan manifest with per-file SHA-256 and bundle hash;
- explicit scope and instruction-policy manifests;
- bounded implementation baseline that excludes large data/output/state trees;
- immutable P0R1 supersession record;
- authorization receipt that records the operator's actual natural-language instruction and its bounded interpretation.

The old P0R1 authorization is already claimed and cannot be copied, upgraded, replayed, or rebound.

## P0R2-T1: Store, bootstrap, and reporting foundation

Public behavior:

- a trusted bootstrap provisions two different fixed-path SQLite stores exactly once;
- an AuthorizationEnvelope is phase/attempt/actor/invocation/hash/expiry bound and one-time claimable;
- ordinary readers receive no generic SQL or authority write connection;
- authority changes and outbox writes commit atomically;
- outbox mirroring is idempotent and a pending row blocks phase closure;
- TaskReport V2 has one strict schema and a builder-computed outcome.

The shared `SqliteUnitOfWork` owns `BEGIN IMMEDIATE`, bounded busy timeout, foreign keys, schema version checks, expected-state CAS, idempotency, UTC timestamps, monotonic sequence, read-only `mode=ro`, and domain error translation. Future schemas, missing stores, corruption, and busy failures fail closed. Authority and operational paths being equal is a configuration error. `ATTACH DATABASE` is forbidden.

`control_plane.task_report.v2` includes plan/phase/task/attempt/authorization identity, objective, dependencies, idempotency key, allowed/forbidden files, baseline ref/hash, input evidence, test receipts, review findings, changed/unexpected files, external invocations, side-effect summary, computed outcome, timestamps, and self hash. `changed_files` is always an array. Usage values are `REPORTED`, `ESTIMATED`, or `UNKNOWN`; unknown numeric fields are null.

Required failure tests include public-hash bootstrap, expired/wrong-phase/wrong-actor/replayed envelope, secret leakage in repr/error/log/JSON, same-path stores, worker SQL access, mirror crash/replay, future schema, deleted/corrupt/locked store, and malformed/self-hash-invalid TaskReport.

## P0R2-T2: Provisional P0R1 adoption

Do not edit the old reports. Verify their byte hashes, identify schema/status, rerun current contract and import-safety tests, compare code deltas, and emit a V2 adoption report.

- T1 implementation may be adopted only after full revalidation.
- T2 scanner behavior and import fixes may be adopted after revalidation.
- the 368-entry inventory is `INITIAL_PROVISIONAL_ONLY`;
- the source-tree `entry_policy.json` never satisfies the final P0R2 gate;
- `BLOCKED_BY_PLAN_REVISION` cannot be normalized into PASS.

## P0R2-T3: Generic gate engine

Build one `PhaseGateBuilder/Verifier/Closer` for P0-P8. The caller cannot submit PASS. A GateReport binds the phase/attempt identity, TaskReport references and hashes, implementation baseline, code-freeze manifest, final inventory, reviewed entry policy, scheduler inventory, tests, open/failed/IN_DOUBT tickets, pending outbox, side effects, file deltas, unresolved risks, computed verdict, `auto_advance=false`, and self hash.

CLI:

```text
python -m research_automation.control_plane.cli gate preflight --phase P0 --attempt-id <id>
python -m research_automation.control_plane.cli gate build --phase P0 --attempt-id <id> --freeze-manifest <path> --inventory <path> --entry-policy <path> --scheduler-inventory <path> --task-report-id <id> --output <path>
python -m research_automation.control_plane.cli gate verify --phase P0 --attempt-id <id> --report <path> --read-only
python -m research_automation.control_plane.cli gate close --phase P0 --attempt-id <id> --report <path> --capability-stdin
```

Expected exit codes are 0 verified PASS, 2 valid computed FAIL, 3 malformed/corrupt evidence, 4 authority/identity mismatch, and 5 unavailable/IN_DOUBT store. Verify runs in a new read-only process. Close re-verifies and atomically records the immutable digest. A formal FAIL requires a new attempt.

## P0R2-T4: Execution sink guards

Guard subprocess, patch, repair, full-cycle, autonomous, experiment, and discovery execution sinks immediately before their first side effect. Revalidate exact entry identity, argv/runner identity, resource roots, ticket, fenced lease, Windows canonical containment/reparse behavior, and immutable execution intent.

Patch application uses an isolated workspace and `git apply --check`; remove `--unsafe-path` from trusted paths. Existing Runner status booleans remain legacy evidence.

## P0R2-T5: Authority writes and legacy-loop quarantine

Guard Registry, Snapshot, Handoff, KBase, automatic repair/writeback, AutonomousRunnerV1, evolution, backlog, and autorun writers. Without a valid ticket they fail before effect. Legacy results are stamped `controller_created=false`, `trust_state=legacy_unaudited`, and `promotion_eligible=false`.

Do not implement Campaign here and do not make TaskQueue, STOP, resume, or status files authoritative.

## P0R2-T6: Web and CLI closure

Guard web writes, LLM thread creation, path deletion, and config mutation. Bind loopback by default and disable debug. Dry run must not construct a Runner, create directories, connect to networks, or spawn processes. `run_research.py` owns the control-plane command registry; root scripts are thin adapters. Unauthorized execution fails before import-time or construction-time effects.

## P0R2-T7: Integration and code freeze

Run targeted tests, control-plane integration tests, the full unittest suite, production-daily non-interference fixtures, and a filesystem allowlist diff. Confirm no real research/backtest/API/KBase/data/Git/scheduler mutation occurred as a consequence of the control-plane code.

Generate a source-freeze manifest after all source and test changes. Any later change in the scanned source/test set invalidates the freeze and returns to T7.

## P0R2-T8: Final inventory and independent policy review

After code freeze, run a stable scanner that does not follow symlinks/junctions/reparse points and excludes data, outputs, caches, and generated state. Any file changing between scan start/end fails the scan. Unknown scheduler evidence remains explicit UNKNOWN.

The scanner creates a candidate only. A separate trusted review publishes the active policy as `research_state/control_plane/policies/<sha256>.json` and records its digest in AuthorityStore. The P0R1 source policy remains provisional evidence.

## P0R2-T9: Official close

PASS requires exact P0R2 identity, all required V2 reports PASS, P0R1 evidence not directly counted, final inventory matching the code freeze, reviewed policy matching inventory, explicit scheduler evidence, no open/failed/IN_DOUBT ticket, zero pending authority outbox, required tests/reviews green, no unexpected scope delta, and no unauthorized side effect.

After close:

```text
P0=PASS
P1_AUTHORIZED=false
CAMPAIGN_AUTHORIZED=false
FINAL_EVAL_AUTHORIZED=false
AUTO_ADVANCE=false
```

Stop at that boundary and wait for a new P1 authorization.

## Why this is a sealed-TCB change

The P4 Learning Commit security review proved that an Authority-valid terminal
TaskReport currently exposes the ticket state, frozen task spec, trusted
receipts, actor, identity, and allowed side effects, but its public read-only
binding does not expose the terminal `task_tickets_v2.evidence_ref` already
stored by Authority.

Consequently P4 can prove that `learning-decision` was a trusted input receipt,
but cannot prove that the terminal task outcome itself named that exact decision.
A `SUCCEEDED` ticket could name another outcome artifact and still be replayed as
a Learning Commit projection.

The master plan seals P0's authority/bootstrap/gate trusted computing base after
P0 PASS and requires a new P0 change request and attempt for any later change.
This request does not reinterpret the broad P0-P8 implementation authorization
as permission to bypass that invariant.

## Requested bounded change

Permit one additive, read-only Authority binding field:

- add `terminal_evidence_ref: str` to `TaskReportAuthorityBinding`;
- populate it only from the already existing, terminal
  `task_tickets_v2.evidence_ref` row after the current full TaskReport authority
  verification succeeds;
- reject missing or empty terminal evidence identity fail-closed;
- expose no generic SQL, query, writer, capability, secret, or mutable object.

Permit P4 Learning Commit to require:

- `binding.terminal_evidence_ref` exactly equals the Authority-bound
  `learning-decision` evidence reference;
- the allowed side-effect set is exactly `{WRITE_CONTROL_PLANE}`;
- the terminal timestamp is normalized to canonical UTC before Authority ledger
  ordering;
- task ID, exact five-item evidence set, output sinks, repository-root baseline,
  runner adapter/version, approved protocol, approved claim, and runner artifact
  remain exact Authority bindings.

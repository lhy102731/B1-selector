# V3.4.2 P1: Typed Foundations and Protocol Identity

## Entry conditions

P1 requires a verified P0R2 gate digest, a new P1 attempt/scope binding, and a separately issued P1 authorization. P0 capabilities cannot be reused. Sealed P0 bootstrap, broker, store schema, gate verifier, and transaction-core files are read-only.

## Typed contract registry and artifact identity

Build one versioned ContractRegistry using strict, frozen, extra-forbid Pydantic models that produce Draft 2020-12 JSON Schema. Unknown versions and unknown fields fail closed. Migration is explicit; no semantic field receives a silent default. The P0 TaskReport/Gate authority validator remains sealed, with a compatible typed reader layered above it.

Separate `ArtifactLocator` from `ArtifactIdentity`. Path, storage root, size, and mtime locate bytes; content SHA-256, byte length, schema, producer, generation, kind, and logical role identify them. Moving equal content does not change identity; changing content does. Directory identity uses an ordered manifest. Lazy fingerprints can inventory data but cannot authorize trusted execution. Historical KBase hashes use a legacy profile and are never rewritten.

## Typed project settings

Create one research/control-plane settings owner with precedence:

```text
explicit CLI/init override > environment > selected env file > YAML > documented default
```

It covers control-plane paths, provider/model/base URL, timeout, retry reference, tokenizer, pricing/usage metadata, budgets, KBase reference, and roster. Production `strategy_params.yaml` remains separate.

Secrets use `SecretStr`; plaintext YAML secrets are rejected or must be environment references. Secrets never enter repr, dumps, schema examples, hashes, task reports, or logs. Read-only inspection works without a secret; invocation fails before network access if one is absent. Importing settings must not load `.env`, mutate `os.environ`, or configure global logging. The existing `ResearchConfig` becomes a compatibility adapter without a repository-wide consumer rewrite.

Declare and lock the minimal direct dependency set. Runtime code never installs packages.

## ExecutionSpec and protocol compiler

Compile a frozen ExecutionSpec binding approved and executed protocol hashes, code, input artifacts, generation, dataset roles, label, horizon, folds, purge, embargo, feature boundary, runner, model/threshold, roster, and conformance.

Conformance is one of `IDENTICAL`, `IMMATERIAL_ALLOWLISTED`, `APPROVED_AMENDMENT`, or `MATERIAL_UNAPPROVED`. Label/horizon, dataset roles, purge/embargo, runner, feature boundary, promotion gate, generation, model artifact, and threshold-selection window are material. A compiler-generated preregistration hash cannot self-approve.

Compatibility adapters may validate, compile dry, diff, inspect artifacts, and show redacted settings. P1 must not execute research, call an LLM, create real outputs, access Holdout, write KBase, or alter Runner selection.

## Gate

Verify deterministic schema/hash output, strict unknown rejection, no secret leakage, stable artifact identity, settings precedence, `ResearchConfig` compatibility, ambiguous/material protocol rejection, finite numeric values, Windows path/reparse containment, dependency preflight, code freeze, final inventory, reviewed policy delta, and the generic phase gate. P2 remains unauthorized.
